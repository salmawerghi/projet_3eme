1. Concept et positionnement

ÉlémentProposition
Nom de travailDarImmo (« dar » = maison). Alternative : ImmoGo
Proposition de valeurTrouver, publier et négocier un bien immobilier depuis un seul endroit, avec une carte interactive et une messagerie intégrée

6. Modélisation C4

La méthode C4 (c4model.com) décrit le système en quatre niveaux de zoom : contexte, conteneurs, composants, code.

Niveau 1 : diagramme de contexte

Les trois acteurs utilisent l'application mobile. Elle s'appuie sur trois systèmes externes : cartes, notifications push (Firebase) et email (envoyé par Supabase Auth).

Niveau 2 : diagramme de conteneurs

Les deux clients mobiles partagent le même backend Supabase. L'administrateur utilise les écrans réservés de l'application mobile ; un back-office web reste un bonus. Les push passent par un trigger, une Edge Function et FCM.

Niveau 3 : composants de l'application mobile

Niveau 4 : code (classe clé)

Exemple pour Annonce : attributs de la section 4, plus fromJson(), toJson() et copyWith(). Elle est associée à un AnnonceRepository (getAll(filters, page), getById(), getMine(), create(), update(), delete(), uploadPhotos()) appelé par un AnnonceViewModel (Provider en Flutter, store Zustand en React Native). Cette architecture (Model, Repository, ViewModel, View) s'applique aux deux versions.
